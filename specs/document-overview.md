# Document Overview (Description, Sections, Cover) — Implementation Plan

## Summary
After a PDF upload, the app shows only title + page count. Add an auto-generated **overview** per document: short summary, detailed description split into formatted sections, metadata next to the name (author, language, doc type, topics, pages, upload date), and a **cover image** (first page render). Generated by an LLM in a separate async worker task after ingestion, so chat readiness is never blocked by a cosmetic feature.

## Success Criteria
- Upload PDF → within ~60 s of `READY`, document has `summary` (≤ 300 chars), 3–6 description sections, language, doc type, 3–6 topics, author (if present in PDF metadata), and a cover.
- Doc list item shows cover thumbnail + 2-line summary; detail page shows cover next to title, metadata row, topic badges, summary, formatted description sections.
- LLM failure (bad JSON, rate limit, no token) never changes `Document.status`; doc stays chat-usable; UI shows Retry/Generate button.
- "Regenerate" button works for old docs (no overview, no cover) and for `failed` overviews.
- List endpoint (`GET /documents`) does not load cover bytes (query size unchanged apart from summary text).
- `lint-imports`, `ruff`, `mypy`, pytest, vitest, `tsc` all green; new unit tests cover parsing, state transitions, use case.

## Scope & Constraints
- **In scope**: migration `0006`; entity/ORM/mapper fields; cover render in `PdfExtractor`; new `DocumentDescriber` port + OpenAI-compatible + Fake adapters; `GenerateDocumentOverview` use case + Celery task; `GET /documents/{id}/cover`; `POST /documents/{id}/overview/regenerate`; frontend list item, detail page, regenerate hook, MSW mocks; tests.
- **Out of scope**: OCR / scanned PDFs (extractor already rejects them); PDF viewer / serving the PDF; map-reduce summarisation of very long books (we sample); editing the description by hand; extracting embedded photos (decision: page-1 render only); fixing pre-existing warts (`chunk_count=len(sections)` placeholder, duplicate-upload re-run, `DocumentRead` importing `DocumentStatus` from infrastructure).
- **Hard constraints**: domain layer stays free of `openai/sqlalchemy/pymupdf/...` (import-linter contract in `apps/api/.importlinter`); cover stored as **bytea in Postgres** (user decision) → must be `deferred` in ORM and never in list queries; LLM step non-fatal (user decision).
- **Trade-offs**: separate task after `READY` (chat usable sooner, extra status field + polling) over inline step in `IngestDocument` (simpler, but couples cosmetic LLM call to ingestion, needs LLM wired in worker ingest path, and ties up the 1800 s time limit). Sampling text over full-doc map-reduce (cheap, bounded by Groq TPM limits; summary quality slightly lower on long books).

## Architecture & Design

### High-Level Flow
```
POST /documents ─► UploadDocument ─► Celery process_document
                                        │ PARSING: extract() + render_cover()  (cover failure = warn, continue)
                                        │ EMBEDDING ... mark_ready(page_count, title, strategy, author)
                                        │ set overview_status=pending, commit
                                        └─► queue.enqueue_overview(id)   ──► Celery generate_overview
                                                                             │ load evenly-sampled chunks + section titles
                                                                             │ DocumentDescriber.describe()  (1 retry on bad JSON)
                                                                             │ save overview, status=ready | failed
Frontend polls GET /documents/{id} while status in (PENDING, PARSING, EMBEDDING) OR overview_status == "pending"
Regenerate button ─► POST /documents/{id}/overview/regenerate ─► overview_status=pending, enqueue_overview
                     (also renders cover if missing → backfills old docs)
```

### Key Changes

**Data model** — migration `apps/api/alembic/versions/0006_document_overview.py` (`down_revision = "0005"`), all nullable, `op.add_column("documents", ...)`:

| column | type | note |
|---|---|---|
| `author` | `String(512)` | PDF metadata |
| `summary` | `Text` | ≤ 300 chars, shown in list |
| `language` | `String(16)` | e.g. `en`, `pl` |
| `doc_type` | `String(64)` | e.g. "Technical manual" |
| `topics` | `ARRAY(String(64))` | 3–6 |
| `description_sections` | `JSONB` | `[{"heading": str, "body": str}]` |
| `overview_status` | `String(16)` | `pending` / `ready` / `failed`; NULL = never generated (old docs) |
| `cover_image` | `LargeBinary` | JPEG ~400 px wide, ~30–60 KB; ORM `deferred()` |
| `cover_mime` | `String(32)` | `image/jpeg`; NOT NULL ⇔ has cover |

`downgrade()` drops the columns. Separate columns (not one JSONB blob) so list endpoint reads `summary/topics/...` cheaply and `WHERE overview_status='pending'` stays trivial.

**Domain** (`apps/api/src/app/domain/`)
- `values/overview.py`: `OverviewStatus(StrEnum)`, `OverviewSection(heading, body)`, `DocumentOverview(summary, language, doc_type, topics, sections)`. Stdlib only.
- `entities/document.py`: add fields `author, summary, language, doc_type, topics, description_sections, overview_status, cover_mime`; property `has_cover`; methods `mark_overview_pending(now)`, `apply_overview(overview)`, `mark_overview_failed()`; `mark_ready(...)` gains optional `author`; `clear_derived`/retry path resets overview to NULL. `updated_at` doubles as staleness marker.
- `ports/repositories.py` `DocumentRepository`: add `get_cover(id) -> tuple[bytes, str] | None`, `set_cover(id, data, mime)`. `ChunkRepository`: add `sample_text(document_id, max_tokens, token_counter) -> str` **or** `list_evenly_spaced(document_id, count)` (verify existing chunk repo API in step 1).
- `ports/storage.py` `PdfExtractor`: add `render_cover(file_path, width_px) -> CoverImage | None`; `ExtractedPdf` gains `author: str | None`. `IngestionQueue`: add `enqueue_overview(document_id)`.
- `ports/llm.py`: new `DocumentDescriber` Protocol: `async describe(title, author, section_titles, sample_text) -> DocumentOverview`.

**Application**
- `usecases/ingestion/ingest_document.py`: call `render_cover` in PARSING (try/except → log, continue); pass `author` to `mark_ready`; after commit, set overview pending + `queue.enqueue_overview`. Enqueue failure is swallowed (log) — overview is optional.
- `usecases/documents/generate_overview.py` (`GenerateDocumentOverview`): load doc (must be `READY`), render cover if missing, build sample (evenly spaced chunks up to `describe_max_input_tokens`, plus section titles list), call describer (1 retry on `ValueError`), `apply_overview` or `mark_overview_failed`, commit. Never raises to the Celery layer.
- `usecases/documents/request_overview.py` (`RequestOverview`): validates doc exists and is `READY`; rejects (`OverviewAlreadyPending`) if pending and `updated_at` < 10 min old; sets pending, commits, enqueues.
- `usecases/documents/get_cover.py`: returns `(bytes, mime)` or raises `CoverNotFound`.

**Infrastructure**
- `infrastructure/pdf/pymupdf_extractor.py`: `render_cover` → page 0 `get_pixmap(matrix=Matrix(s, s))` scaled to width 400 → `pixmap.tobytes("jpeg", jpg_quality=80)`; author from `doc.metadata["author"]` (strip, empty → None). Encrypted/corrupt → `None`.
- `infrastructure/llm/adapters.py`: `OpenAIDescriber` (same `AsyncOpenAI` client as reranker), prompt: system = "You describe documents. Reply JSON only, in the document's own language: {summary, language, doc_type, topics, sections:[{heading, body}]}"; parse with existing `_extract_json_object`; validate + clamp (summary ≤ 300 chars, topics ≤ 6, sections 3–6, drop empty); `ValueError` on invalid. `FakeDescriber` (deterministic, used when `llm_token` unset). `build_describer(settings)`.
- `infrastructure/config/settings.py`: `describe_model="openai/gpt-oss-120b"`, `describe_max_input_tokens=8000`, `describe_max_tokens=3000` (gpt-oss reasoning tokens count against `max_tokens`).
- `infrastructure/db/models/document.py` + `mappers.py` (both create and update branches!) + `repositories.py` (`get_cover` selects the deferred column explicitly; `set_cover`).
- `infrastructure/queue/celery_queue.py` + `interfaces/worker/tasks.py`: new task `generate_overview(document_id)`, `acks_late=True`, `time_limit=300`, `autoretry_for=()` (use case handles failure itself). `interfaces/worker/composition.py`: `get_generate_overview()` builds describer + extractor.

**HTTP** (`interfaces/http/`)
- `schemas/documents.py`: `DocumentRead` += `author, summary, language, doc_type, topics, overview_status, has_cover`; `DocumentDetail` += `description_sections: list[SectionDescription]`. Import `OverviewStatus` from **domain** (not infrastructure).
- `routers/documents.py`:
  - `GET /documents/{id}/cover` → `Response(content=bytes, media_type=mime, headers={"Cache-Control": "private, max-age=3600"})`, 404 if none.
  - `POST /documents/{id}/overview/regenerate` → 202 `DocumentRead`; 404 not found; 409 not READY / already pending.
- `composition.py`: DI for new use cases.

**Frontend** (`apps/web/src/`)
- `libs/api/documents/types.ts`: extend `Document` (`author, summary, language, doc_type, topics, overview_status, has_cover`) and `DocumentDetail` (`description_sections`). `api.ts`: `regenerateOverview(id)`, `documentCoverUrl(id)` (uses base URL from `client.ts`).
- `features/documents/components/DocumentCover.tsx`: `<img>` with `aspect-[3/4]`, `loading="lazy"`, lucide `FileText` placeholder when `!has_cover` or on `onError`.
- `DocumentListItem.tsx`: cover thumbnail (w-12) left, title, `line-clamp-2` summary, existing badges/buttons kept.
- `DocumentPage.tsx`: header = cover (w-28/32) + right column: title, badges (`doc_type`, `language`), meta row (author · N pages · uploaded date), topic badges, summary. Below: `OverviewSections` card (`## heading` + paragraph per section). States: `pending` → Skeleton; `failed` → `Alert` + "Regenerate" button; `null` on READY → "Generate description" button; non-READY doc → nothing.
- `hooks/useRegenerateOverview.ts` (mutation, invalidates `documents` + document detail query). `useDocuments`/`useDocument` `refetchInterval` also true while `overview_status === "pending"`.
- `test/handlers.ts` mocks updated; MSW handlers for new endpoints.
- Text is rendered as plain React text (no `dangerouslySetInnerHTML`, no markdown) → LLM output from untrusted PDFs cannot inject HTML.

### Alternative Approaches Considered
- **Where to run LLM**: (A) inline in `IngestDocument` — simpler, but overview failure/latency delays `READY`, requires LLM in ingest wiring; (B) **separate Celery task after READY — chosen**: chat available immediately, isolated failures, reusable for Regenerate; (C) on-demand at first view — unpredictable latency, per-user cost.
- **Cover source**: (A) **page-1 render — chosen**, always works; (B) largest embedded image — often logos/figures, not covers; (C) hybrid — extra complexity, revisit later.
- **Cover storage**: (A) **bytea in Postgres — chosen (user decision)**, one backup, no volume mgmt; cost: must defer column, ~50 KB/row; (B) file on disk + endpoint — lighter DB but new storage lifecycle (delete cascade). Migration path to (B) is easy behind `get_cover/set_cover`.
- **Section semantics**: (A) **LLM description sections — chosen (user decision)**; (B) TOC-based chapter outline — already exists as `sections` table, could be added later.
- **Structured LLM output**: (A) **prompt "JSON only" + `_extract_json_object` — chosen**, consistent with `OpenAIReranker`, works on Groq; (B) `response_format=json_schema` — not confirmed supported by the provider, deferred.

## Risks & Mitigations
- **LLM returns invalid JSON / wrong shape** (no native JSON mode).
  - Mitigation: reuse `_extract_json_object`, strict validation + clamping, 1 retry, then `overview_status=failed` + Regenerate button.
- **Groq rate limit (TPM) on long text**.
  - Mitigation: hard input cap `describe_max_input_tokens=8000` via `TokenCounter`; even sampling; failure is non-fatal and retryable by user.
- **Overview stuck in `pending` (worker died)** → UI polls forever.
  - Mitigation: `RequestOverview` allows re-request when pending and `updated_at` older than 10 min; task `time_limit=300`; frontend shows Regenerate after the same staleness threshold.
- **Cover bytea bloats list/detail queries.**
  - Mitigation: `deferred()` column, `has_cover` derived from `cover_mime`, cover fetched only in `get_cover`; add a test asserting `list_newest_first` SQL doesn't select `cover_image`.
- **Page 1 is blank / a copyright page / dark** → ugly cover.
  - Mitigation: accepted for v1; follow-up: pick first page with enough non-white pixels.
- **Prompt injection via PDF text** (e.g. "ignore instructions").
  - Mitigation: output only used as plain text fields, length-clamped, no tool use, rendered escaped in React.
- **Forgetting a mapper branch** → field silently not persisted.
  - Mitigation: repo round-trip integration test for every new field.

## Test Strategy
- **Unit (`pytest -m unit`)**: `Document` overview transitions; `has_cover`; describer JSON parsing (fenced, prose-wrapped, missing keys, >6 topics, empty sections); sampling stays under token budget and is evenly spread; `GenerateDocumentOverview` with fake uow/describer/extractor (success, describer error → failed & status untouched, not READY → no-op, cover backfill); `RequestOverview` conflict rules.
- **Integration (docker infra)**: repo round-trip for all new columns; `render_cover` on factory PDF returns valid JPEG (magic bytes, width ≈ 400); `GET /cover` 200 + headers / 404; `POST regenerate` 202 / 404 / 409; list query doesn't load cover.
- **Frontend (vitest + MSW)**: `DocumentListItem` (summary clamp, cover fallback on `onError`), `DocumentPage` states, regenerate mutation + invalidation, polling continues while `overview_status==="pending"`.
- **Manual**: upload a text PDF (EN) and a PL PDF → check language, sections, cover; kill worker mid-generation → stale pending recovery; unset `LLM_TOKEN` → Fake describer works; upload old doc → Generate button backfills cover + description.
- **Performance**: single describe call ≤ ~8k input tokens; cover ≤ 100 KB; `GET /documents` payload growth = summary text only.
